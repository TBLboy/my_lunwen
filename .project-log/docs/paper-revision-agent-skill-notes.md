# 论文写作与修改 Agent Skill 素材

## 1. 材料用途

这份文件不是论文正文，也不是最终的 Skill 规范。它记录本项目从连续拒稿、修改定位、补充实验、重绘图片到模板迁移和最终排版验证所形成的可复用思路。

未来设计“结合材料写论文或修改论文”的 Skill 时，应把本文件作为：

1. 工作流和规则候选来源；
2. 反例与失败模式库；
3. Skill 输入、输出和验证门槛的设计依据；
4. 后续复盘时区分“项目事实”和“通用经验”的入口。

本文件中的项目案例是证据，不自动等同于通用规则。未来 Skill 必须有适用边界和反例处理。

## 3. 核心工作模型

论文修改不能从“改句子”开始。应先建立以下链条：

```text
期刊范围与审稿问题
-> 论文主张
-> 支撑主张的实验证据
-> 缺口或过度声明
-> 修改方案
-> 图表与页面预算
-> 正文修改
-> 编译与视觉验证
-> 跨章节一致性复核
```

核心判断原则：

1. **审稿意见先分类，再执行。** 期刊 scope 不匹配、论文创新不足、论证缺口、实验覆盖不足、格式或语言问题不能使用同一种修改方式。
2. **先保护主贡献，再决定是否扩实验。** 不能因为审稿人提出一个方向，就把它升级为新的论文主线。
3. **每个结论都必须有对应证据。** 缺少实验支持的稳健性、泛化性或优越性表述必须缩小范围或补证据。
4. **页面预算是实验设计的一部分。** 增加实验内容不等于等量增加长度；必须通过图表重排、合并和正文压缩控制体量。
5. **图表是论证结构，不是正文附属品。** 每张图应回答一个明确问题，并与正文中的结论一一对应。
6. **不能发明材料事实。** 作者、单位、基金、数据可用性、AI 使用声明、控制器参数和实验指标都必须有材料或用户确认。
7. **用户决定产品语义。** 当问题涉及论文主线、实验取舍、作者信息或跨期刊策略时，先给出推荐方案和影响，等待用户确认。
8. **没有验证不声明完成。** LaTeX 论文至少需要干净编译、引用检查、页数检查和受影响页面渲染检查。

## 4. 推荐的 Agent 修改流程

### Phase 0：恢复材料和事实

必须完成：

- 找到当前正式稿、正文、参考文献、图片、数据和期刊模板；
- 阅读目标期刊的作者指南；
- 恢复当前任务、上一步修改、有效证据和未决问题；
- 确认哪些数据、模型和图片是当前有效版本；
- 检查 Git 状态，不能覆盖用户或其他任务的未提交修改。

输出：

- 当前事实快照；
- 可用材料清单；
- 已知缺口和缺失输入；
- 当前页面预算和目标期刊。

### Phase 1：审稿意见分类

把每条意见分配到一个主分类：

| 分类 | 含义 | 默认动作 |
|---|---|---|
| 期刊范围 | 内容适合另一类期刊 | 影响投稿选择，不强制修改论文核心 |
| 贡献表达 | 创新点、必要性和差异没有讲清 | 重写 gap、动机、贡献和对比 |
| 理论缺口 | 假设、稳定性、复杂度或适用域不清 | 补证明、限制条件或清晰限定 |
| 实验缺口 | 平台、轨迹、基线、扰动或泛化不足 | 设计最有信息量的补充实验 |
| 数据与复现 | 指标、窗口、模型、控制器或数据来源不清 | 回到原始数据和运行记录复核 |
| 写作与格式 | 摘要、图表、引用、模板、页数 | 在主张和证据冻结后处理 |

分类后记录：

- 采纳、部分采纳、拒绝或仅用于选刊；
- 修改成本；
- 是否改变论文主线；
- 需要的新实验或新材料；
- 推荐理由和潜在副作用。

### Phase 2：建立 claim-evidence 矩阵

每条主要主张至少记录以下字段：

| 字段 | 内容 |
|---|---|
| Claim ID | 便于引用和追踪 |
| 主张原文 | 摘要、引言、方法、实验或结论中的表述 |
| 证据 | 公式、定理、数据、图、表或引用 |
| 实验条件 | 平台、轨迹、数据划分、窗口、控制器参数 |
| 对比对象 | EDMD、EDMDDL、PID、局部线性化等 |
| 结论边界 | 适用范围和不能外推的情形 |
| 状态 | supported、partial、unsupported、conflicting |
| 修改动作 | 保留、补证据、限定措辞或删除 |

典型案例：

- 论文声称两个平台都验证了鲁棒性，但扰动恢复实验只在机械臂上进行。正确处理是把扰动结论限定到机械臂，而不是删除软体平台实验。
- 软体平台建模只展示 trajectory 66。材料中的平均 RMSE 不支持“软体平台整体优于所有基线”的说法，因此正文只能围绕展示轨迹和已报告指标表述。

### Phase 3：决定修改路线

按以下顺序选择动作：

1. 能否通过重构论证解决，而不增加实验？
2. 能否使用已有数据和模型生成更有说服力的图表？
3. 能否增加一个小规模、目标明确的交叉平台验证？
4. 是否必须新增物理实验或重训练？
5. 如果证据无法获得，是否应删除或缩小结论？

本项目选择：

- 保留 FS-EDMD + robust Koopman-LQR 为主贡献；
- 把软体平台定位为交叉平台验证，而不是新论文；
- 不为迎合控制领域审稿意见增加局部 Jacobian 线性化 LQR；理由是机械臂当前不具备方便重实验的条件，而且 Koopman 本身是全局线性化路线，局部线性化对比不能直接回答当前主问题；
- 控制实验继续使用 FS-EDMD-LQR 与 PID 对比；
- 通过机械臂和软体平台双平台、多个轨迹和数据指标加强实验覆盖；
- 通过紧凑图片和精简正文控制页面体量。

### Phase 4：实验与图表规划

实验规划先写“结论需要什么证据”，再决定图。

建议实验矩阵：

| 研究问题 | 平台 | 数据/轨迹 | 对比对象 | 指标 | 输出图或表 |
|---|---|---|---|---|---|
| 模型是否更准确 | 机械臂、软体平台 | held-out rollout | FS-EDMD、EDMD、EDMDDL | MSE、RMSE、MAE | 两个建模图 + 表 |
| 控制是否更准确 | 机械臂、软体平台 | 多个参考轨迹 | FS-EDMD-LQR、PID | RMSE、MAE | 两个控制图 + 表 |
| 扰动下是否有界恢复 | 机械臂 | sinusoidal +扰动 | 仅 FS-EDMD-LQR | 轨迹恢复和指标 | 复用机械臂控制图 |

本项目的图表面向用户的最终决定：

- Figure 1：系统或框架图；
- Figure 2：控制器结构；
- Figure 3：实验设备；
- Figure 4：机械臂建模精度；
- Figure 5：软体平台建模精度；
- Figure 6：机械臂控制；
- Figure 7：软体平台控制；
- 图片按首次引用顺序命名；
- 旧图、未引用图片和不再使用的指标文件应被清理。

### Phase 5：正文修改

修改时保持以下顺序：

1. 摘要；
2. 引言的问题、空白、方法和贡献；
3. 方法中的假设和边界；
4. 实验设置；
5. 结果和讨论；
6. 结论；
7. 最后处理语言和模板细节。

实验变化后必须检查旧表述是否失效，尤其是：

- “single platform”“a real robot”等数量表述；
- 摘要是否声称两个平台都完成了某项实验；
- 贡献列表是否遗漏新增验证；
- 图号、表号、章节导览和交叉引用；
- 结论是否与摘要使用同样强的措辞。

### Phase 6：编译与视觉验证

至少执行：

```text
从干净副本复制正式源码
-> latexmk -pdf -interaction=nonstopmode main.tex
-> 检查退出码
-> 扫描 Overfull、Underfull、未定义引用、缺图和 fatal error
-> 检查最终页数
-> 渲染摘要页、实验页、图表页和结论页
-> 人工检查遮挡、断页、空白、字号和图宽一致性
```

不要直接在 Overleaf 源目录留下 `.aux`、`.log`、`.bbl`、`.pdf` 等构建缓存，除非项目明确要求。

### Phase 7：跨章节一致性复核

最终使用同一组问题进行全文扫描：

1. 摘要中的每个结论是否在结果中存在？
2. 引言的贡献是否与方法和实验一致？
3. 实验对象数量和平台名称是否更新？
4. 图表是否支持正文中的“更准确、更稳健、更高效”等比较词？
5. 结论是否超过摘要和实验范围？
6. 指标、参数、窗口、单位和缩写是否前后一致？
7. 引用顺序和参考文献列表是否一致？

## 5. 摘要检查清单

目标不是写满，而是形成完整闭环：

```text
问题 -> 方法 -> 理论性质 -> 实验验证 -> 有边界的结论
```

必须检查：

- 是否在期刊字数限制内；
- 是否说明现有方法的具体失败模式；
- 是否说明为什么采用该特定方法，而不是只写“proposed”；
- 是否给出核心理论结果和适用条件；
- 是否说明实验平台、对比对象和主要发现；
- 是否避免把只在部分平台验证的结论写成跨平台普遍结论；
- 缩写采用分层规则：LQR、ReLU、PID、PCA、MSE、RMSE、MAE 等本领域常见缩写可直接使用；EDMD、EDMDDL、FS-EDMD 等非通用或论文自定义缩写必须在首次出现前给出全称；
- 摘要和正文分别检查首次出现；标题中的标准缩写不为了形式统一而强行展开；
- 是否避免空泛的 “improved performance”“demonstrates effectiveness”。

本项目实际修正案例：

- 原文：两个平台的实验都 “demonstrate improved ... robustness”。
- 问题：扰动恢复只在机械臂上进行。
- 修正：双平台用于建模和多轨迹控制验证，鲁棒性明确限定为机械臂扰动恢复测试。

推荐结构示例：

1. 背景技术及其一般能力；
2. 具体瓶颈和错误模式；
3. 本文方法与关键机制；
4. 优化或理论结论；
5. 控制器或应用设计；
6. 两平台实验与有边界的结论。

## 6. 引言与结论检查清单

推荐逻辑：

```text
系统重要性
-> 现有一阶建模或数据驱动路线
-> 选定方法的基本思想
-> 关键瓶颈
-> 现有解决方案为何仍不足
-> 本文方法及必要性
-> 贡献列表
-> 章节导览
```

重点检查：

- 贡献是否只有方法贡献，而新增实验完全没有进入贡献叙事；
- 贡献是否与摘要和结论重复但表述不一致；
- 是否明确说明“为什么需要这一特定方法”；
- 是否区分“实现了某方法”和“证明该方法必要”；
- 是否保留对 scope 类审稿意见的正确边界：选刊失败不自动意味着理论有问题；
- 章节导览是否仍在使用旧实验数量或旧平台名称；
- 术语是否统一，例如 rigid robot arm、soft platform、test trajectory、rollout。
- 不把“所有缩写都必须展开”当作机械规则；只对读者可能不认识或由本文命名的新缩写强制要求“全称（缩写）”。

本项目实际修正案例：

- 引言原有 “experimental validation results on a real robotic platform”，在新增软体平台后已过时；
- 贡献列表增加双平台验证，使实验扩展进入论文叙事；
- 使用更直接的短句替代重复的 “To this end”“this paper proposes”“The innovations and contributions ...”。

### Conclusion

Conclusion 应总结已经完成并得到证据支持的工作，而不是重新宣传、扩展主张或引入新结论。

重点检查：

- 理论结论是否与实际证明条件一致；
- 实验结论是否与最终图和表一致；
- 是否把只在部分平台完成的测试写成全部平台结论；
- 是否明确说明当前结果适用的运行范围、扰动设定和实验条件；
- 是否区分模型预测对比、控制器跟踪对比和扰动恢复测试；
- Future work 是否从当前限制自然延伸，而不是突然变成另一篇论文；
- 摘要、引言、实验结果和 Conclusion 是否使用同等强度的措辞。

本项目实际修正案例：

- 原句把两个平台的实验共同概括为 improved prediction accuracy、tracking performance 和 robustness against external disturbances；
- 实际证据是两个平台都支持预测和跟踪改善，而扰动恢复只在机械臂上进行；
- 修正后明确写出双平台的预测和跟踪结果、机械臂单独的扰动恢复结果，以及 tested operating ranges 和 bounded-disturbance setting 的限制。

## 7. 图、表和页面规则

### 图

- 一图一问：每张图回答一个可写进正文的问题；
- 单栏和小图优先，线条可放大查看；
- 同一实验的多张子图优先放在同一行或同一结构组；
- 子图标签不能遮挡曲线；
- 图例和标题应靠近绘图区，避免大块空白；
- 多图之间线宽、字体、颜色和尺寸应统一；
- Figure 编号必须按正文首次引用顺序；
- 图片更新后删除旧文件，并重命名引用文件；
- 设备照片未更新前可使用旧图，但必须在材料中标记待替换。

### 表

- 表格只保留支持核心比较的数据；
- 如果空间不足，简单数据可写入正文；
- 所有方法使用相同窗口和单位；
- 指标定义放在表注或正文；
- 不使用用户明确决定放弃的指标；
- 软体平台与机械臂应尽可能保持同一指标口径。

### 页面预算

本项目的预算最终为 9 页以内，由用户决定；RAS 指南没有硬性 9 页限制。

实际操作原则：

- 增加实验内容，但不增加实验章节的物理体量；
- 通过拆图、重排、合并、缩放和删除冗余数据实现；
- 图片不宜一味缩小到不可读；
- 如果图被移动后造成空白，应回到正文顺序和图片尺寸寻找原因；
- 页面目标由用户最终判断，Agent 不把自己的页数假设写成期刊规则。

## 8. 数据、指标和复现检查

每批数据使用前检查：

- 文件格式和字段是否完整；
- 控制器身份是否与文件名和导出元数据一致；
- step 是否单调、唯一和完整；
- 是否存在重复的终端监控样本；
- reference、输入和状态长度是否一致；
- 不同控制器的采样数是否一致；
- 时间轴是否可靠，是否需要按 step 或归一化进度对齐；
- 指标窗口是否一致；
- 图使用完整轨迹还是评估片段；
- 正文数值能否从脚本重新得到。

本项目的代表性问题和处理：

- 导出文件名或元数据曾错误标记 PID 为 Koopman-LQR，最终必须由用户确认控制器身份，不能根据文件名猜测；
- 新 CSV 末尾有 30 个重复终端行，绘图和指标前必须按 step 去重；
- Lissajous 的 FS 数据为 1000 点，PID 为 500 点，忽略不稳定时间轴并对 FS 做 2 倍降采样后按 sample index 对齐；
- 指标计算必须使用统一的初始化排除窗口，避免不同实验使用不同时间窗口。

## 9. 语言和“人写感”检查

“human-made-like”不是故意降低质量，而是减少模板化、空泛和堆叠式表达。

优先使用：

- 具体主语和动作；
- 明确的对比对象；
- 具体实验结果；
- 受证据约束的结论；
- 自然的段首过渡；
- 一致的术语和时态。

常见 AI 式症状：

- 每段都使用 “To address this issue”；
- 反复使用 “this paper proposes a novel framework”；
- “experiments demonstrate improved performance” 但没有说明和谁比较、改善了哪一部分；
- 把不同平台、不同实验和不同结论合并成一个大而全的句子；
- 为了显得全面而重复摘要、引言和结论；
- 用 “robust”“general”“effective” 代替条件和范围；
- 过度使用破折号、三段式和整齐排比。

修改示例：

- 差：Experiments on two platforms demonstrate improved modeling accuracy, tracking performance, and robustness.
- 好：The two platforms are used to evaluate prediction and tracking. A separate disturbance-recovery test on the arm shows bounded deviation and smooth recovery.

语言规则是启发式，不是自动检测结论。最终仍需结合领域习惯和期刊风格判断。

## 10. Agent 交互和决策规则

- 能从材料和已验证事实判断的，不询问用户；
- 涉及论文主线、作者事实、实验取舍、控制器身份、数据可用性、期刊目标或页面预算的，必须先确认；
- 提问一次只问最高影响的问题，并给出推荐答案；
- 用户明确推翻技术建议时，应记录决定和理由，不继续争辩；
- 外部 GPT 或绘图助手可以生成候选图片，但 Agent 必须复核数据、指标、尺寸、文字和论文整合；
- 用户对已确认图片布局或术语的偏好应作为后续一致性的约束。

## 11. 未来 Skill 的建议输入契约

未来 Skill 至少需要：

1. 当前论文源文件；
2. 目标期刊和作者指南；
3. 审稿意见或编辑拒稿意见；
4. 已有数据和模型；
5. 现有图和绘图代码；
6. 参考文献库；
7. 页面和投稿约束；
8. 作者、基金、数据和 AI 使用等事实；
9. 不能改变的贡献、结论或用户偏好；
10. 需要保留的未完成项和开放问题。

## 12. 未来 Skill 的建议输出

建议生成以下可审计产物：

### `revision-brief.md`

- 期刊范围；
- 审稿意见分类；
- 核心主张；
- 主要缺口；
- 修改策略和风险。

### `claim-evidence-matrix.yaml`

- 每条主张；
- 支持证据；
- 结论边界；
- 是否需要新增实验；
- 对应正文位置。

### `revision-plan.md`

- 章节级修改；
- 实验级修改；
- 图表级修改；
- 页面预算；
- 依赖和阻塞条件。

### `figure-table-plan.md`

- 每个图回答的问题；
- 使用数据和评估窗口；
- 对比方法；
- 尺寸和排版位置；
- 图号和引用顺序。

### `change-ledger.yaml`

- 修改内容；
- 原因；
- 证据；
- 是否改变科学结论；
- 用户确认状态。

### `verification-report.md`

- 编译命令和退出码；
- 页数；
- 警告；
- 引用；
- 渲染页面；
- 未验证项。

## 13. 未来 Skill 的质量门槛

必须在以下条件全部满足后声明修改完成：

- 每条主要结论都有证据或明确限定；
- 摘要、引言、实验和结论一致；
- 所有新增数据可以从原始材料复现；
- 图表按引用顺序编号并已人工检查；
- PDF 干净编译且页数满足用户约束；
- 无未定义引用、缺图、明显 Overfull/Underfull 或遮挡；
- 作者指南中的机器可检查项通过；
- 需要用户提供的事实没有被 Agent 猜测；
- Project Log、决策和验证证据已更新。

## 14. 尚未解决的问题

未来 Skill 还需要单独设计和验证：

- 如何处理没有源代码、只有 Word 或 PDF 的论文；
- 如何支持从零写作，而不只是修改；
- 如何管理跨语言翻译和母语化；
- 如何在不伪造文献的前提下建议新引用；
- 如何将期刊模板差异抽象成可配置检查项；
- 如何评价“human-made-like”的语言质量；
- 如何区分一次项目的特殊取舍和可复用规则；
- 如何与用户的个人写作风格和术语表长期同步。

## 15. 最小结论

一个可靠的论文修改 Skill 不应只是“润色器”，而应是一个以材料为事实源、以主张和证据为核心、以图表和页面预算为约束、以编译和视觉检查为验收门槛的修订工作流。
